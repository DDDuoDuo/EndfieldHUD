# Original cursor ownership on Windows

The adapter uses the approved [PlayerSettings cursor manifest](../../Resources/WatchSource/Cursor/player-default.json) and [original PNG](../../Resources/WatchSource/Cursor/player-default-icon_mouse.png). Its SHA-256 is checked before Windows Imaging Component decodes it. `CreateIconIndirect` receives a top-down 32-bit premultiplied BGRA DIB and a transparency AND mask. The native cursor retains the source's 58 × 58 physical pixels and `(0, 0)` hotspot. No resampling, generic replacement icon, second GPU pointer or cursor hide-count change is introduced.

This follows the Mac adapter's source size/hotspot and event ownership policy in [HUDSourceWatchView.swift](../../Sources/HUDSourceWatchView.swift) and [HUDRenderedCursor.swift](../../Sources/HUDRenderedCursor.swift). The Windows implementation selects one native OS cursor path. The Mac implementation also draws its source pointer into the HUD while holding a balanced hide lease to work around Mac recording behavior; the Windows choice still requires an actual recorder test. GPU drawable readback intentionally does not contain the native pointer.

Initialize `RenderedCursor` on the owner HWND's UI thread after COM initialization. Pass the staged `Resources/WatchSource/Cursor` directory. A missing, corrupt, mismatched or malformed original resource returns a failure; an existing cursor survives a failed reload. The object retains one owned HCURSOR and destroys temporary WIC/GDI bitmap resources after conversion.

The host supplies visible/focus/pointer-acceptance lifecycle states and resolves the current `CursorRegion` from its projected editor and child-control hit tests. Presentation includes opening and closing until actual concealment. Source controls becoming disabled during an animation do not disable the whole-window cursor. Lifecycle setters release ownership when ineligible and never blindly acquire it from a stale pointer position. An explicit event callback or one lifecycle pointer query resolves the fresh region before `refresh()`.

Process `WM_SETCURSOR` only for the owner HWND and `HTCLIENT`; return `TRUE` when `handle_set_cursor` handles it. Native child regions and nonclient resize/move hits fall through to their native handler without an intermediate cursor selection. For a projected editor or other host-owned native shape, select its I-beam/resize cursor before marking the region native. The source owner releases its lease without replacing a native cursor already chosen. `WM_MOUSELEAVE`, concealment, focus loss, pointer disablement and detachment must update the respective state before teardown.

Bracket menus, native dialogs, native-control tracking and OLE drags with nested `begin_native_tracking()`/`end_native_tracking()` calls. Every begin releases any source ownership. Tracking completion leaves reacquisition to the host's next fresh arbitration, including a synchronous lifecycle query if the pointer did not move. Native tracking vetoes all source cursor refreshes until the outermost scope ends. Release restores the preceding shape only when `GetCursorInfo` still reports this object's own cursor; another application's or native control's selection is preserved. There is no polling/display timer, deferred forced repair, pointer warp or class-wide cursor mutation.

`snapshot()` reports native dimensions/hotspot, source hash, ownership, retained handles, creation/destruction counts, cursor selections, restorations and preserved foreign cursors. It queries no cursor state. `rendered_cursor_tests` uses an unshown HWND, the actual approved bitmap, WIC/CreateIconIndirect/GetIconInfo and isolated memory-DC readback. Cursor selection/query calls are replaced by fixture hooks, so the test changes neither the user's pointer nor desktop pixels. It checks source pixel/orientation/mask preservation, native precedence, nested tracking, focus/close/exit restoration, rejected resource reloads, 100 retained reopen cycles and 100 native recreation cycles. It does not establish live recording or accessibility pointer enlargement.

Live acceptance remains **unverified** until Windows built-in recording and the saved video show the HUD and the original cursor without duplication, missing pixels or alternating arrows. Also check real native dialogs/drags, hover on projected editing, focus changes to another application, mixed-DPI monitor transitions, and Windows accessibility pointer size settings. The original game's runtime cursor overrides remain separately unverified, as the source manifest states.

Microsoft documents [alpha cursor creation and ownership](https://learn.microsoft.com/en-us/windows/win32/menurc/using-cursors), [CreateIconIndirect bitmap copying](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-createiconindirect), [WM_SETCURSOR arbitration](https://learn.microsoft.com/en-us/windows/win32/menurc/wm-setcursor), and [global cursor queries](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getcursorinfo). These APIs establish the implementation contract; they do not certify how an external recorder saves a hardware cursor.
