# Notes canvas

Open **Notes** in the right navigation. Its add controls stay in the center HUD; note cards can move anywhere across the full overlay screen, outside the circular content area.

- **Text:** press Text to add a note immediately. Type directly in the note. Double-click its body to edit again. Escape or Command-Return saves; Return inserts a new line. Scroll vertically to read long notes; the header stays fixed. The native editor preserves the reading position and remains open while scrolling. The square size, font, current-color and special-style controls appear only while editing. Select a range, then use these bottom-left controls. The secondary style row beneath the note provides bold, italic, underline and strikethrough. Formatting affects the selection (or future typing at a caret); mixed fonts, sizes and colors persist independently.
- **TODO:** press TODO to add a checklist immediately. Edit a row and press Return to save. Use **+ Add item**, the checkbox, the up/down arrows, or the row's × to manage the checklist. Long tasks wrap across multiple lines; completed tasks have strikethrough. Scroll continuously through long checklists with a mouse wheel or trackpad, including fractional movement and native momentum. Header and add-item controls stay fixed.
- **Image/Video:** choose a Finder source or an item from the in-HUD Shelf picker. Its bounded, retained scrolling list offers a media filter and disables unsupported/unavailable entries. Drop image/video files anywhere in Notes; Command-V also accepts copied media files or image data when no text editor is active. GIF plays while visible, with a play/pause control. Native video starts paused and offers play/pause plus a thin seek rail; dragging previews a position and sends one seek on release. VoiceOver can also adjust the position. Supported codecs depend on the installed macOS AVFoundation decoders. Unsupported contents show an explicit error, regardless of filename extension. To drag from Finder into the full-screen HUD, first visit Notes and close the HUD, pick up the media, then summon the HUD with the configured shortcut (Ctrl + backtick by default) while holding it.
- **Drawing:** add a spatial drawing card, then hold the left mouse button to draw. The circle follows the pointer and shows the current brush diameter; the wheel adjusts it from 1 to 80 logical points. Right-click toggles a stroke eraser (red cursor), which removes touched strokes. The bottom-left color button opens an in-HUD color wheel, also operable with arrow keys. Drawings resize with their cards. Limits are 2,000 strokes, 4,096 points per stroke and 100,000 points per note; reaching a limit reports it and preserves earlier work. Only completed gestures write to storage.
- Drag a note's header to move it. Text and image bodies can also be dragged. Drag the lower-right corner to resize. Selecting a note brings it forward.
- Pinning keeps a note visible when switching to another HUD section; pinned notes remain movable, resizable and editable. Unpinned notes return when reopening Notes. The header’s × or Delete/Backspace opens a small **× / ✓** confirmation immediately below the header’s ×: × cancels, ✓ deletes. Closing the HUD hides every note.

Cards retain screen coordinates and share the side buttons’ tilt, mouse travel and response timing without circular clipping. Pinned notes keep the same motion on other sections. Dragging, resizing and native text editing hold the current pose steady; pointer motion resumes afterwards. Adding, changing and removing notes use short depth/reveal animations; hiding the HUD cancels their finite animation tracks. Reduce Motion disables perspective motion. The native text input supports selection, undo, copy/paste and Chinese input methods without opening another editor window. The overlay remembers the last visited section until the app quits.

Formatting, media-source and Shelf menus use the Personal Card's retained face, offset backplate and cut-corner hover frames. Their visible layers inherit the same tilt as the HUD; transparent native adapters use inverse-projected hit tests and provide accessibility. Font choices and Shelf media create only visible row artwork, with no native dropdown or flat scrolling-window background. The first outside click dismisses the menu. Opening formatting tools releases the text editor's pose lock; while the menu moves, native glyph layout stays fixed rather than re-encoding the document on every pointer event. Closing the menu reconciles its scale once and preserves mixed runs and the caret's pending formatting. The editor uses explicit white ink on dark surfaces and black ink on light surfaces; explicit user-selected colors remain unchanged. Bold/italic/underline/strike apply one consistent state across mixed selections. System font payloads store size and traits through the public system-font API rather than private `.SFNS` names. The first formatting action removes fixed plain-text paragraph heights before changing a selection or pending typing style, so large characters in the middle of a line are not clipped.

Reading a text note uses the space beneath its hidden formatting tools, down to an eight-point bottom inset. Only active editing reserves the tools' footer. All Notes submenus render above the note workspace, including checklists and deletion controls. Center-based media menus convert their geometry to that same workspace before projection, keeping their artwork, mouse input and accessibility aligned. Every in-HUD submenu reveals with a 0.14-second fade/movement and dismisses over 0.12 seconds. Dismissal releases input immediately and retains at most one outgoing face; hiding Notes cancels it. Reduce Motion changes menus immediately, without animations or a cleanup timer.

## Perspective while editing

Notes/TODO, Work Mode custom time, Add App names, Personal Card fields and Archive share `HUDProjectedTextEditor`. The real `NSTextView` remains first responder and owns TextKit layout, rich attributes, undo and marked-text composition at stable logical dimensions. Text and selection render into one bounded visible-viewport image on the existing HUD plane; a separate retained caret follows AppKit's insertion-point callback. The adapter never transforms an AppKit-owned backing layer. The native scroll surface has zero compositing opacity: guarding `draw(_:)` alone is insufficient because AppKit retains an independent text ContentLayer, which can otherwise display another copy at the screen origin. Child glyph capture remains full opacity, so only the HUD-owned artwork is visible. Optional grey placeholders are projected artwork and never enter text storage, undo or saved documents. Editor presence does not freeze the HUD. Finder, color and permission dialogs remain native system surfaces.

Pointer selection and scrolling use the same inverse projection as each canvas. `firstRect(forCharacterRange:actualRange:)`, `characterIndex(for:)` and accessibility text-range geometry map between logical text and projected screen coordinates; pose changes invalidate the input context's character coordinates without relaying out or recapturing text. Text/selection/scroll invalidations coalesce onto the main queue. There is no new repeating timer. The image is limited to 2,097,152 pixels (8 MiB of RGBA pixels), at most 4,096 pixels per side, even for long notes or horizontally scrolling single-line fields. Closing releases the input surface, observers and image. No schema, text limit, or edit-save policy changes are required.

Isolated regression coverage verifies actual native glyph capture, native insertion-point placement, projected mouse clicks, candidate and accessibility range geometry, marked-text survival/commit, undo, fractional scrolling, bounded long-note artwork, and zero recaptures during 120 pose updates. The 27 shared-editor assertions include complete offscreen native-window snapshots with a TextKit view that deliberately paints independently of the draw guard. They verify a blank native origin, visible projected text before and after edits, retained first responder, and projected-only placeholders. A mutation removing the composition suppression fails the native-origin pixel assertion. Adapter tests cover validation, cancellation, Return/Tab, focus-loss commit and composition-safe limits. The native Batch34 diagnostic also exercises Notes and Profile on the real HUD plane and exports editor previews. Physical Chinese input-method/candidate-window behavior and spoken VoiceOver navigation remain unverified; protocol-level marked-text and accessibility-geometry tests do not substitute for those manual checks on the final build. See Apple's [backing-layer ownership guidance](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/CoreAnimation_guide/CreatingBasicAnimations/CreatingBasicAnimations.html), [text-input client contract](https://developer.apple.com/documentation/appkit/nstextinputclient) and [input-coordinate invalidation](https://developer.apple.com/documentation/appkit/nstextinputcontext/invalidatecharactercoordinates()).

## Storage

Notes are local to this Mac, in `~/Library/Application Support/EndfieldCharge/Notes/notes.sqlite3`. Each record stores its UUID, type, text/checklist content, image reference, x/y, width/height, z-order, creation time and pinned state. Geometry uses logical overlay-screen coordinates. Existing records remain in the same database. A smaller screen keeps cards accessible through display-only clamping without rewriting their saved position or size.

Changes commit after text editing, a checklist action, or the end of a drag/resize. Closing the overlay, changing sections and quitting finish active edits. SQLite transactions keep failed writes from replacing committed records; failures are shown inside Notes. An unreadable database is preserved instead of replaced.

Existing image notes and pasted image bytes retain their managed PNG behavior: at most 1,600 pixels, stored in the adjacent `Images` directory. Removing an image note removes its managed copy only after the database commit and only if no note still references it. New file-based images, GIF and videos store security-scoped bookmarks instead of copying originals. Keep those original files available; missing access is reported without deleting or replacing the saved reference. Animated GIF is limited to 2,000 frames, image sources to 128 MB / 64 megapixels. Decoded display dimensions and GIF frame caches are bounded; video uses AVPlayerLayer and releases its item when hidden. A video installs one native 1 Hz progress observer only while visibly playing. Only its retained 2-point progress rail and 5×8-point handle interpolate between updates; pausing, hiding or disposing removes the observer. No audio capture, private API or new permission is used.

Closing and section transitions stop media playback and scoped access immediately. One already-decoded bounded image remains for at most 0.6 seconds so the outgoing card does not turn blank; videos use their existing poster. This one-shot visual release is cancelled on reopening or disposal. Drawing and media artwork subtrees are excluded from control-hover traversal.

There is no network service, polling, or database timer. Diagnostic UI/smoke sessions use a separate temporary directory and do not change saved user notes.

Scrolling offsets are temporary view state and never write to SQLite. Measured line layouts use a 64-entry cache with a 16 MiB budget for retained line-range allocation. A new width, font or text measurement replaces the old layout for that note or task. The most recently used single layout may exceed the budget for an unusually long document; it remains cached so scrolling does not repeatedly typeset the whole document, and no user text is truncated. Drawing retains only visible text lines and checklist rows within each note's clipped content area. Task drawing, pointer actions, accessibility and inline-editor bounds share the same row measurements. Resizing reflows text and clamps the reading position without changing saved content.

Database version 2 adds nullable rich-text, media and drawing payload columns in one SQLite transaction. Existing note IDs, text, checklist data, image names, geometry, order, timestamps and pins remain intact. Canonical text stays in the original text column; formatting uses validated UTF-16 ranges without arbitrary RTF attachments. Drawing uses the existing text storage kind with a versioned vector payload. Unknown database/payload versions and corrupt rows fail closed, preserving the database. Failed media/format/drawing commits preserve earlier records. A cancelled import discards its pending completion and releases its scoped access. No full file scan or idle media timer is added.

The original `origin/codex/endfield-watch-motion` resource inventory was searched for drawing, pen/paint, edit, photo/picture/camera/video, color and font assets before choosing controls. Text and TODO continue to reuse the original Operational Manual and Mission artwork. No specifically applicable drawing/media/format toolbar bitmap could be identified in that inventory; the new controls use small code-drawn/text glyphs. The Drawing add button reuses the Personal Card introduction pencil path; Text and TODO glyphs sit slightly higher to align with their labels. No generated image, duplicate asset bundle or external dependency was added.

## 中文

在右侧选择**便笺**。点击**文字**或**待办**立即添加对应便笺；点击**图片**选择图片，也支持拖入或粘贴图片。添加按钮保留在中央，便笺可在整个浮层屏幕内移动，不受中央圆形区域限制。

双击文字便笺编辑，按 Esc 或 Command-Return 保存。长文字支持上下连续滚动，编辑时滚动不会退出输入框。待办事项按 Return 保存；通过复选框、上下箭头、× 和“添加事项”管理清单。长任务自动换行，已完成任务显示删除线；长清单支持鼠标滚轮和触控板的连续滚动，标题栏和添加按钮保持固定。拖动标题栏移动，拖动右下角调整大小。固定的便笺在切换其他模块时仍显示，也能继续移动、缩放和编辑；关闭浮层时一并隐藏。点击标题栏 × 或按 Delete 后，标题栏 × 下方出现 **× / ✓**：× 取消，✓ 确认删除。编辑时仍可使用中文输入法。添加、修改和删除带短暂过渡，关闭浮层会清理动画。

便笺与两侧按钮采用相同的倾斜、鼠标移动幅度和响应速度，固定后在其他模块中也保留相同效果。拖动、缩放和文字编辑时暂时保持当前姿态，完成后继续响应鼠标；开启系统“减少动态效果”时停用透视运动。

便笺在原有本机 SQLite 数据库中保存，位置与大小采用整个浮层的逻辑坐标。较小屏幕上的临时位置限制不会覆写已保存的几何数据。关闭浮层和切换模块都会完成当前编辑。已有托管图片及直接粘贴的图片数据保留独立副本；新导入的媒体文件采用书签引用。

滚动位置仅在当前界面中保留，不会逐次写入数据库。排版缓存最多保留 64 项，行范围索引分配预算为 16 MiB；同一便笺或任务调整宽度后立即替换旧排版。单篇特别长的当前文档可超过预算，以免每次滚动都重新排版，不会截断文字。

文字仅在编辑时显示左下角的方形字号、字体、当前颜色和特殊格式按钮。选中文字后单独修改格式；二级菜单位于便笺下方，支持粗体、斜体、下划线和删除线。不同文字范围的字体、字号、颜色可分别保存。图片／视频可从 Finder、拖入文件或暂存架选择；GIF 仅在可见时播放，视频使用系统支持的原生解码器，提供细进度条和拖动跳转；松开后才提交一次跳转。仅在可见且播放时保留每秒一次的进度观察，暂停和隐藏立即移除。新文件保存书签引用，不复制大视频，原文件不可用时显示错误。已有托管图片继续保留。

格式、媒体来源和暂存架菜单随浮层继续倾斜；第一次点击菜单外只关闭菜单。打开格式菜单时解除文字输入的姿态锁定，保留正在编辑的内容和选择范围。菜单沿用个人名片的面板、底板和切角悬停边框；命中测试使用反向投影，不采用系统默认下拉菜单。深色编辑背景使用明确的白色默认文字，浅色使用黑色，用户自定义颜色不变。关闭时立即停止解码和文件访问，只保留最多 0.6 秒的小尺寸静态画面完成退场过渡，重新显示或删除时会取消这次延迟清理。

画画便笺内左键拖动画线，滚轮调整 1–80 点粗细，圆圈显示画笔大小；右键切换橡皮擦，擦除碰到的整条笔画。左下角按钮打开颜色轮盘，也能使用方向键操作。只在松开鼠标时保存；每篇最多 2000 笔、每笔 4096 点、总计 10 万点，达到上限会提示且保留已有内容。数据库以事务升级至版本 2，新增格式、媒体和画画字段，保留所有原有数据和固定状态；损坏或未来版本不会被替换。
